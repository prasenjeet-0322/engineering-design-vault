🧪 Lab 02: Layout Thrashing & Forced Reflow Benchmark

Level 04 — KPI 01: Browser Architecture & Process Model (Part 03)

This benchmark demonstrates the massive performance penalty of Forced Synchronous Layout (Layout Thrashing). We will manipulate 800 DOM elements using two different execution strategies.

⚙️ Benchmark Controls

Click a button to measure execution duration in milliseconds.

🧠 Systems Engineering Takeaway:

  • Layout Thrashing (❌): Interleaving card.offsetWidth (Read) and card.style.width (Write) forces Blink to recalculate the entire layout tree 800 times synchronously during the loop!
  • Batched Updates (✅): Reading all values in a first pass, then writing all new styles in a second pass allows Blink to perform exactly 1 single layout recalculation at the end of the task.
